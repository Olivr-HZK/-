# 数据库路径说明

## 📋 概述

项目使用 SQLite 数据库存储竞品数据，数据库文件位置有特定的查找逻辑。

## 📁 数据库文件位置

### 默认路径

数据库文件默认位置：**项目根目录下的 `db/competitor_data.db`**

```
项目根目录/
├── db/
│   └── competitor_data.db  ← 数据库文件（默认位置）
├── database/               ← 数据库模块代码
│   ├── competitor_db.py
│   └── history_db.py
└── ...
```

### 路径查找逻辑

代码会按以下顺序查找数据库目录：

1. **环境变量 `COMPETITOR_DB_DIR`**（如果设置）
2. **项目根目录下的 `db/`**（推荐）
3. **Docker 环境的 `/app/db/`**（如果存在）
4. **如果都不存在，创建项目根目录下的 `db/`**

## ⚠️ 重要说明

### 不要使用 `database/db/` 目录

**注意：** 项目重构后，代码可能会在 `database/db/` 目录下创建数据库文件，但这不是推荐的位置。

**推荐做法：**
- 统一使用项目根目录下的 `db/` 目录
- 如果发现 `database/db/` 目录下有数据库文件，应该：
  1. 检查两个数据库文件的内容
  2. 合并数据到项目根目录的 `db/competitor_data.db`
  3. 删除 `database/db/` 目录

## 🔧 配置数据库路径

### 方法一：使用环境变量（推荐）

在 `.env` 文件中设置：

```bash
COMPETITOR_DB_DIR=/path/to/your/db
```

### 方法二：代码中指定

```python
from database.competitor_db import CompetitorDatabaseDB

# 指定数据库路径
db = CompetitorDatabaseDB(db_path="/path/to/competitor_data.db")
```

### 方法三：命令行参数

某些工具脚本支持 `--db-path` 参数：

```bash
python scrapers/daily_scraper.py --db-path /path/to/competitor_data.db
```

## 🔍 检查当前使用的数据库

### 查看数据库路径

```python
from database.competitor_db import CompetitorDatabaseDB

db = CompetitorDatabaseDB()
print(f"数据库路径: {db.db_path}")
```

### 检查数据库文件

```bash
# 查看项目根目录的数据库
ls -lh db/competitor_data.db

# 查看 database/db 目录（如果存在）
ls -lh database/db/competitor_data.db 2>/dev/null || echo "不存在"
```

## 🚨 常见问题

### Q1: 为什么有两个 db 目录？

**原因：** 代码在查找数据库路径时，如果项目根目录的 `db/` 不存在，可能会在 `database/db/` 下创建数据库文件。

**解决方案：**
1. 确保项目根目录下有 `db/` 目录
2. 如果 `database/db/` 下有数据库文件，检查并合并数据
3. 删除 `database/db/` 目录

### Q2: 如何迁移数据库？

如果需要在两个数据库文件之间迁移数据：

```bash
# 1. 备份两个数据库
cp db/competitor_data.db db/competitor_data.db.backup
cp database/db/competitor_data.db database/db/competitor_data.db.backup

# 2. 使用 SQLite 工具合并数据（需要手动操作）
# 或者使用 Python 脚本合并
```

### Q3: Docker 环境中的路径

在 Docker 容器中，默认路径是 `/app/db/competitor_data.db`。

可以通过环境变量或挂载卷来指定：

```yaml
# docker-compose.yml
environment:
  - COMPETITOR_DB_DIR=/app/data/db
volumes:
  - ./db:/app/db
```
